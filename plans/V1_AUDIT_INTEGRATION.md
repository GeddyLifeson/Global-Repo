False-positive / false-negative risk:
- Lenient direction (misses real bugs): lang keys, models, loot tables and token matches count as "defined"; any diaithir:/diaithir_integration: id matching any word in startup scripts passes; ids in pw.toml namespaces and vanilla are never judged; a recipe whose ingredient is defined but cannot be obtained is not flagged.
- Strict direction (false alarms): items registered in Java with no asset files (class-string scan shows hits for most, because paths like "iron" are common words, so that scan is NOT evidence), runtime-generated ids, fluids/blocks written as items, ingredient-type markers I could not exclude.
- KubeJS script recipes (ServerEvents.recipes in server_scripts) are not parsed; scanning their string literals gives 3,320 hits that are recipe ids ("diaithir:wear/..."), so it was dropped.
